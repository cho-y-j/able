# ABLE 설계 결정 기록 (ADR)

> **목적**: 이미 폐기한 접근을 다시 제안하지 않게 한다.
> 착수 전 반드시 읽는다. 여기서 폐기된 접근을 다시 구현하려면 **먼저 이 ADR을 뒤집는 새 ADR을 써야 한다.**

## 형식

```
## ADR-NNNN 제목
- 날짜 / 상태: 채택 | 폐기 | 대체됨(→ADR-NNNN)
- 맥락: 무슨 문제였나
- 결정:
- 근거:
- 버린 대안과 이유:
- 되돌릴 조건: 어떤 증거가 나오면 이 결정을 재검토하는가
```

## ADR-0001 측정 장치를 알파보다 먼저 고친다
- 날짜: 2026-09-26 / 상태: 채택
- 맥락: 백테스트 엔진이 알파 0인 랜덤워크에서 **Sharpe 10 내외**를 보고한다.
  커밋된 재현 스크립트(`docs/research/scripts/proof_lookahead.py`, `default_rng(7)`) 실행값은 **9.99**,
  L-0001 의 초기 측정값(레거시 `np.random.seed(7)`)은 10.74 다 — RNG 차이이며 결론은 동일 (L-0003)
- 결정: 검증 인프라가 신뢰 가능해질 때까지 **새 알파를 탐색하지 않는다.** 활성화 API는 검증 지표를 출력하지 못하는 전략을 거부한다
- 근거: 측정 장치가 틀리면 그 위의 모든 작업이 손실로 증폭된다. 잘못된 신뢰는 규모만 키운다
- 버린 대안: "알파 탐색과 검증 개선을 병행" — 병행하면 검증되지 않은 알파가 먼저 실거래에 붙는다
- 되돌릴 조건: 없음. 이건 원칙이다

## ADR-0002 백테스트는 벡터 연산이 아니라 체결 시뮬레이터로 만든다
- 날짜: 2026-09-26 / 상태: 채택
- 맥락: `position * daily_returns` 방식이 1봉 룩어헤드를 구조적으로 허용한다
- 결정: 봉 단위 이벤트 루프로 재작성한다. "t 신호 → t+1 주문 → 호가·유동성 확인 → 체결 또는 미체결 → 비용 차감"
- 근거: 룩어헤드가 **구조적으로 불가능**해진다. 상하한가·VI를 체결 실패로 표현할 수 있다
- 버린 대안: 벡터 연산 유지 + `shift(1)`만 추가 — 룩어헤드는 막지만 선물·해외·숏·미체결을 표현할 수 없다
- 예외: `CLAUDE.md` 2.2절 — 이 루프는 의도적이며 벡터화 금지 대상이다. 정확성이 속도보다 우선
- 되돌릴 조건: 시뮬레이터 속도가 실사용 불가 수준이고, 프로파일로 병목이 루프임이 증명될 때

## ADR-0003 단일 고성과 전략 대신 저상관 약한 전략의 앙상블
- 날짜: 2026-09-26 / 상태: 채택
- 결정: 개별 Sharpe 0.3~0.8을 목표로 하고 결합으로 1.0~1.5를 만든다. 백테스트 Sharpe 2 초과는 결함 신호로 취급한다
- 근거: 단일 고성과 패턴은 거의 확실히 과최적화다. 횡단면으로 가면 표본이 커져 DSR 판정이 비로소 가능해진다
- 버린 대안: 고Sharpe 단일 패턴 탐색 — 표본 부족으로 DSR이 거의 항상 음수이며 판정 자체가 불가능
- 되돌릴 조건: 없음

## ADR-0004 리스크 한도는 하드코딩이며 LLM·최적화기가 수정할 수 없다
- 날짜: 2026-09-26 / 상태: 채택
- 결정: 일손실·총노출·단일종목·DD 한도는 결정론적 규칙으로 L7에 둔다. 알파 계층이 이 값을 바꿀 수 없다
- 근거: 확률적 출력으로 손실 한도를 정하면 안 된다. 기존 `risk/limits.py`·`circuit_breaker.py`가 이미 이 구조이며 유지한다
- 되돌릴 조건: 없음

## ADR-0005 LLM은 예측기가 아니라 연구자로만 쓴다
- 날짜: 2026-09-26 / 상태: 채택
- 결정: 아래를 **금지**한다 — 실시간 매매 판단, 백테스트 루프 내 LLM 호출, 뉴스 감정 → 진입 신호, 가격 예측, 리스크 한도 판단.
  아래를 **허용**한다 — 가설 생성(인과 서사 강제), 공시·재무 → 구조화 피처(마스킹+컷오프 검증), 연구 자동화, 적대적 감사, 사후 설명
- 근거:
  - 학습데이터 오염. LAP(Lookahead Propensity) 지표가 **인샘플 구간 전체에서 유의하게 양(+)이고
    학습컷오프 직후 사실상 0으로 붕괴**한다 (arXiv:2512.23847). ※ 이전 판에 있던 "상승 확률 0.9999"는
    초록에서 확인되지 않은 수치였으며 삭제했다 — **ADR-0013 참조**
  - 백테스트에 LLM이 들어가면 컷오프 이전 성과가 암기일 수 있어 **측정 자체가 불가능**해진다
  - 에이전트 서베이(arXiv:2608.31041) 원문: **"강한 모델·예측 능력이 라이브 시장 조건과 신뢰성 통제
    하에서 트레이딩 성과로 안정적으로 전환되지 않는다."** 집행·리스크는 기존 방식 유지 권고.
    ※ 이전 판의 "대부분의 에이전트가 매수보유를 이기지 못한다"는 **원문보다 강한 패러프레이즈**였다 — ADR-0013
  - **주 정량 근거 (더 강함)**: Agent Market Arena (arXiv:2510.11695, ACM WWW 2026) **Table 1** —
    4자산 × 에이전트 4종 × LLM 5종 = 80개 조합 중 **매수보유를 이긴 것은 13개(16.25%)**.
    BTC 에서 InvestorAgent 0/5, TSLA 에서 HedgeFundAgent 0/5.
    **거래비용·슬리피지를 모델링하지 않았으므로 16.25%는 상한이다.**
    같은 논문 초록은 "often outperforming buy-and-hold"라고 쓴다 → **초록이 아니라 표를 인용한다**
  - LiveTradeBench (arXiv:2511.03628, 21 LLM, 50일): **매수보유 베이스라인 부재를 저자들이 자기 지식 공백으로
    명시**하고 비용·유동성·슬리피지 생략을 명시한다. **LMArena 점수와 트레이딩 성과 상관 ρ≈0.05(주식),
    −0.38(예측시장)** → 모델을 키워도 트레이딩이 좋아지지 않는다
- 검증 절차: ① 컷오프 이후 구간에서만 최종 검증 ② 컷오프 전후 성과 격차 측정 ③ 종목·날짜 마스킹 후 재측정 ④ LLM 없는 규칙 근사와 비교
- 되돌릴 조건: 오염을 배제한 설계에서 LLM이 규칙 근사를 유의하게 능가함이 컷오프 이후 데이터로 입증될 때

## ADR-0006 뉴스 감정은 알파가 아니라 필터다
- 날짜: 2026-09-26 / 상태: 채택
- 맥락: "뉴스에 파는 세력" 문제. 뉴스 직후 가격은 정보 반영가가 아니라 주목도에 밀린 과잉반응가다
- 결정: 뉴스 감정 점수를 **진입 신호에 연결하지 않는다.** 회피·청산 필터로만 쓴다.
  - 뉴스 + 거래량 급증 + 개인 순매수 우위 → 신규 진입 금지, 청산 우선순위 상승
  - 뉴스 부재 + 거래량 완만 증가 + 외국인·기관 순매수 지속 → 중기 알파 가중 상향
  - 뉴스는 이벤트 시각 정렬(무엇이 언제 공개됐는가)에 쓴다 — 룩어헤드 차단 목적
- 근거: Barber & Odean(2008) 개인은 주목도 기반 매수, 최고 거래량 구간에서 매수가 매도보다 29.5% 많음.
  개인 주목도는 발표 후 변동성을 높이고 가격 조정을 지연시키며 특히 부정적 뉴스 확산을 지연시킴
- 버린 대안: LLM 뉴스 감정 → 매수 신호. 이 경로는 기관이 넘기는 물량을 받는 쪽에 선다
- 되돌릴 조건: 수급으로 조건화한 감정 신호가 컷오프 이후 데이터에서 유의한 알파를 보일 때

## ADR-0007 거래량은 방향 신호가 아니라 조건변수다
- 날짜: 2026-09-26 / 상태: 채택
- 결정: 거래량을 독립 알파로 쓰지 않는다. 다른 알파(특히 모멘텀)의 **가중치를 조절하는 변수**로 쓴다.
  Amihud류 유동성 지표는 알파가 아니라 **비용 추정·주문 크기 한도**에 쓴다
- 근거: Lee & Swaminathan(2000) — 저거래량 승자는 3년까지 추세 연속, 고거래량 승자는 2~3년차 반전.
  같은 모멘텀 신호가 거래량에 따라 정반대 결론을 낳는다
- 버린 대안: "거래량 급증 = 매수" 규칙. 급증은 정보 도착일 수도 주목도 충격일 수도 있고 후자면 반전이 온다
- 되돌릴 조건: 없음

## ADR-0008 단기 전략은 국내 현물이 아니라 지수선물로 한다
- 날짜: 2026-09-26 / 상태: 채택 (수치 검증 전)
- 맥락: 국내 현물 왕복 비용. **※ 아래 수치는 2026-01-01 세율 인상 전 기준이며 과소추정이다 —
  ADR-0014 에서 정정. 현행 거래세는 KOSPI·KOSDAQ 모두 0.20%** (KOSPI 0.05% 거래세 + 0.15% 농특세).
  정정 전 기록: 대형주 왕복 0.3~0.4%, 코스닥 소형주 0.8~2.2%
- 결정: 단기(1~5일) 호라이즌은 지수선물로 구현한다. 국내 현물은 중기, 해외 현물은 장기에 배치
- 근거: 단기 알파 기대수익이 1~2%면 현물 비용이 수익의 20~100%를 먹는다. 기술이 아니라 산수의 문제.
  **파생상품에는 거래 단위 거래세가 사실상 부과되지 않고, 이익에 파생상품 양도소득세 11%
  (지방소득세 포함, 기본공제 250만원, 국내·국외 파생 손익통산)가 부과된다 — 회전율과 무관한 사후 과세다.**
  코스피200(미니 포함) 선물이 과세대상. ※ 이전 판의 "증권거래세가 없다"는 부정확했다 — **ADR-0014 참조**.
  여기에 양방향(공매도 제약 없는 숏)과 베타 헤지 수단이 따라온다
- 위험: 레버리지. **L7 한도를 명목금액이 아니라 증거금 기준 노출로 재정의하는 작업(Q-032)이 선물 연동(Q-033)보다 먼저다**
- 미확정: 선물 수수료율·증거금률·틱가치·실측 왕복비용. **확정된 것: 코스피200 선물 거래승수 25만원,
  미니 5만원(1/5).** 파생상품거래세 탄력세율 현행 여부는 확인 실패(미확인). 구조적 논지는 확정, 수치는 미검증
- 되돌릴 조건: 실측 왕복 비용이 예상과 크게 다를 때

## ADR-0009 구조 재설계는 하되 백지 재작성은 하지 않는다
- 날짜: 2026-09-26 / 상태: 채택
- 맥락: 현재 스키마가 다호라이즌·다자산을 표현할 수 없다는 판단
- 결정: **재작성** — `models/`(strategy·order·position·factor_snapshot), `backtest/engine.py`, `validation/` 4파일, `pattern_discovery.py`, `scoring.py`.
  **이식** — `integrations/kis/`, `execution/`(646행), `risk/limits.py`, `circuit_breaker.py`, `human_approval.py`, `frontend/`, Celery·DB 골격, 테스트 인프라, `indicators/`·`signals/` 계산부
- 근거: KIS 연동과 집행 알고리즘, 리스크 게이트는 검증된 자산이며 병목이 아니다. 다시 만들면 수개월이 사라진다
- 버린 대안: 전면 백지 재작성 / 기존 스키마에 컬럼만 추가하는 패치. 후자는 `UNIQUE(..., stock_code)` 제약 때문에 횡단면 전략을 끝내 표현할 수 없다
- 되돌릴 조건: 마이그레이션 비용이 재작성 비용을 초과함이 드러날 때

## ADR-0010 과거 `WORK_LOG.md`의 `✅ 완료`를 검증 근거로 쓰지 않는다
- 날짜: 2026-09-27 / 상태: 채택
- 맥락: `WORK_LOG.md:13` "백테팅 엔진(벡터화) ✅ 완료" — 해당 엔진은 룩어헤드 결함이 확인됨 (L-0001)
- 결정: 과거 로그의 `✅ 완료`는 `구현됨`으로 해석한다. `검증됨`의 근거로 인용하지 않는다.
  앞으로 `완료`라는 단어를 쓰지 않고 다섯 개 상태 어휘만 쓴다
- 근거: 기존 스키마가 "코드를 썼다"와 "동작을 검증했다"를 구분하지 않았다. 구분 없는 기록은 결함을 보이지 않게 만든다
- 버린 대안: 과거 561행 전체를 재분류 — 비용이 크고 이득이 작다. 헤더 주의문 + 이 ADR로 대체
- 되돌릴 조건: 없음

## ADR-0011 제1원칙 — 최고의 AI 자동매매 프로그램
- 날짜: 2026-09-27 / 상태: 채택
- 근거: 사용자 명시 지시. "최고의 AI 자동매매 프로그램이 되어야 함이 제1원칙이다.
  최근 수많은 프로그램들이 나오고 있는데 가장 이상적인 프로그램이 되어야 한다."
- 결정: 이 원칙이 ADR-0001~0010 위에 선다. 충돌 시 이 원칙이 이긴다.
  단 **"최고"의 정의는 아래와 같이 한정한다.** 정의하지 않으면 원칙이 아니라 구호다.

### "최고"의 조작적 정의

| 기준 | 최고의 의미 | 아닌 것 |
|---|---|---|
| 수익 | 검증을 통과한(DSR>0, PBO<0.5) 실거래 성과 | 백테스트 수익률 숫자 |
| 신뢰 | 측정이 거짓말하지 않음. 지표가 재현 가능 | 화려한 대시보드 |
| 생존 | MDD 15% 이내, 자동 강등이 작동 | 고수익 후 계좌 소멸 |
| 확장 | 3축 격자(호라이즌×자산군×정보원)를 하나의 체계로 담음 | 기능 목록 길이 |
| 운영 | 구현과 검수가 분리된 자동 개발 파이프라인 | 사람이 매번 확인 |

### 이 원칙이 금지하는 것 (중요)

"최고"를 노리다 무너지는 경로를 명시적으로 차단한다.

1. **기능 나열로 최고를 주장하지 않는다.** 검증되지 않은 기능은 부채다.
2. **경쟁 제품이 한다는 이유로 도입하지 않는다.** ADR로 근거를 먼저 쓴다.
3. **AI를 더 쓰는 것이 더 좋은 것이 아니다.** ADR-0005 금지선은 이 원칙에 종속되지 않는다 —
   에이전트 서베이가 확인한 사실은 "라이브 평가에서 대부분의 에이전트가 단순 매수보유를 못 이긴다"이다.
   AI를 늘려 최고가 되는 것이 아니라, AI를 **올바른 자리에만** 써서 최고가 된다.
4. **게이트 A·B를 우회하지 않는다.** 속도를 위해 검증을 건너뛰면 원칙 위반이다.
5. **동시에 여러 축을 반쯤 만들지 않는다.** 하나를 끝까지 관통시킨다.

### 차별점 가설 (검증 대상, 사실 아님)

- A: 한국시장 투자자별 매매동향(개인/기관/외국인 일별)은 미국에 없는 데이터 → 구조적 우위
- B: 경쟁 제품은 "검증 엄격성"을 팔지 않는다 → 정직한 측정이 제품 차별점
- C: 단기를 지수선물로 옮기는 비용 논리를 반영한 리테일 제품이 드물다
- D: 구현/검수 분리 자동 파이프라인이 제품 신뢰도를 높인다

**이 네 가설은 외부 증거로 검증되기 전까지 사실로 취급하지 않는다.** 경쟁 조사 결과로 갱신한다.

- 되돌릴 조건: 없음. 단 "최고"의 조작적 정의는 증거에 따라 개정될 수 있다

## ADR-0013 정정 — ADR-0005 의 인용이 원문보다 강하다

## ADR-0014 정정 — ADR-0008 의 세율이 낡았고 파생 과세 서술이 부정확하다

## ADR-0015 규제 경계 — 개인 사용과 타인 배포
- 날짜: 2026-09-27 / 상태: 채택
- 맥락: 경쟁 조사가 이 주제에 대한 결정 기록이 **0건**임을 지적했다. 제품화 시 가장 먼저 부딪히는 벽이다
- **사실**:
  - **2026-04-12 금감원이 핀플루언서 5건을 적발했고 그중 1건이 자동매매 프로그램 제작·판매**다.
    "투자판단을 대체" 했다고 보아 **미등록 투자일임업**으로 판단
  - 판례는 갈린다. 인천지법 2017노1649(2018-02-21)은 **소프트웨어 + 기본 설정값만 제공**한 행위에
    "자동화된 매매거래시스템 자체를 자문이라 대입하기 어렵다"며 죄형법정주의로 **무죄**.
    다만 유사투자자문업 **신고 의무**(자본시장법 §449③6, 과태료) 가능성은 인정.
    대법원 2018도4413(2022-10-27)도 이 영역 판례
  - **코스콤 로보어드바이저 테스트베드**가 제품화 경로다. 통과율 약 80%, 심사 항목은
    분산투자 구조·투자자 성향 반영·보안 체계. 통과 시 영상통화 비대면 일임계약 허용.
    **수익률 광고는 코스콤 공시 1년 이상** 필요
- **결정**:
  1. **이 시스템을 타인에게 판매·대여·구독 제공하지 않는다.** 소유자 1인 자기자본 운용에 한정한다
  2. 무죄 판례의 범위는 "소프트웨어 + 기본 설정값 제공" 이다. **우리처럼 신호를 생성해 주문까지 내는 구조는
     그 범위 밖일 가능성이 높다.** 배포 시 미등록 투자일임업 리스크를 진다
  3. 외부 사용자를 붙이기 전에 이 ADR 을 뒤집는 새 ADR 을 쓴다. 그 ADR 은 유사투자자문업 신고 또는
     투자일임업 등록, 실질적으로는 코스콤 RA 테스트베드 경로를 포함해야 한다
  4. **성과 수치를 대외 공표하지 않는다.** 수익률 광고에 코스콤 공시 1년 이상이 요구된다
- 되돌릴 조건: 법적 검토를 받고 등록·신고 경로를 확정했을 때

## ADR-0016 차별점 판정 — ADR-0011 가설 A~D 의 검증 결과
- 날짜: 2026-09-27 / 상태: 채택
- 맥락: ADR-0011 이 차별점 4개를 가설로 두고 외부 증거 검증을 요구했다. 경쟁 조사가 판정했다
- **가설 A (한국 수급 데이터 = 구조적 우위) → 부분 반증**
  - "미국에 없다"는 **틀렸다.** Boehmer·Jones·Zhang·Zhang(2021, Journal of Finance)이 TAQ sub-penny 로
    리테일 주문불균형을 구성했고 **상위-하위가 다음 1주 약 10bp, 최대 12주 정보성**을 보인다.
    Nasdaq RTAT 같은 상용 제품도 있다. 미국에 없는 것은 데이터가 아니라
    **거래소가 공표하는 3주체 분류의 깨끗함·무료·일별 granularity** 다
  - "드물다"도 **약하다.** 젠포트가 약 300개 팩터에 외국인/기관 수급을 이미 포함한다(무료, 실계좌 연동).
    무명 오픈소스도 거래대금 정규화 수급을 쓴다
  - **수정된 명제 (이것은 지지됨)**: 접근성 자체는 우위가 아니다. 우위는
    **반감기 실측 + 다중검정 보정 + 비용 예산과 결합된 정식화**에서만 나오며 그 결합을 한 제품은 발견되지 않았다
  - 방어 가능성: **6~18개월** (아이디어는 이미 유통 중)
- **가설 B (정직한 측정이 차별점) → 조건부 지지, 범위 축소**
  - 반증: Composer 는 OOS 구간 자동 예약 + 과최적화 회피 교육을 마케팅에 쓴다.
    QuantConnect 는 "백테스트할수록 성과를 할인하라"를 가르치고 Parameter Detector·랜덤데이터 스트레스를 제공한다.
    **한국에는 코스콤 RA 테스트베드라는 정부 주도 제3자 검증이 제도화**되어 있다
  - **빈 칸은 "정직한 측정" 전체가 아니라 다중검정 보정(DSR/PBO/시행횟수 로깅)이라는 좁은 칸이다.**
    DSR 을 네이티브 계산하거나 시행횟수를 추적하는 리테일 플랫폼을 하나도 찾지 못했다 — QuantConnect 포함
  - 장벽은 기술이 아니라 **인센티브**다. 시행횟수를 세면 사용자가 본 백테스트 숫자가 할인 표시된다.
    젠포트(알고리즘 100만개)·Tickeron(로봇 다수 공개) 같은 모델은 도입할 수 없다
  - 방어 가능성: **구조적으로 2~3년.** 코드는 모방 가능하나 "표시하기로 한 결정"이 방어선
- **가설 C (단기를 선물로) → 지지, 그리고 강화됨**
  - 2026-01-01 거래세 인상으로 논리가 더 강해졌다 (ADR-0014)
  - 이 논리를 제품 구조에 넣은 리테일 제품을 **발견하지 못했다**
  - 방어 가능성: **중간, 1~3년**
- **가설 D (구현/검수 분리 파이프라인이 제품 신뢰도를 높인다) → 불충분. 부분 반증**
  - "개발 프로세스가 트레이딩 제품 신뢰도·성과를 높인다"는 외부 증거를 **하나도 찾지 못했다.**
    사용자가 개발 프로세스를 구매 근거로 삼는다는 증거도 없다
  - 시장이 보상하는 것은 프로세스가 아니라 **제3자 검증된 결과**다 (코스콤 공시 1년)
  - **우리 원장이 반대 증거를 담고 있다**: L-0009(감독자가 검수 전 커밋), L-0007(프롬프트 문자열 손상으로
    루틴이 항목 선택 실패할 상태), L-0006/Q-008(클라우드 에이전트 로드 미검증).
    파이프라인은 `구현됨`이며 `검증됨`이 아니고 **자기 결함을 이미 3건 생산했다**
  - **단 내부 도구로서의 가치는 지지된다** — 이 파이프라인이 있었기에 L-0001~L-0013 이 기록되고
    ADR-0005 인용 과장과 ADR-0008 세율 노후화가 발견됐다. **내부 가치와 제품 차별점을 섞지 않는다**
- 결정: ADR-0011 의 차별점 목록을 위 판정으로 교체한다.
  **1순위는 가설 B 의 좁은 칸(다중검정 보정)이다** — 유일하게 비어 있는 상위 칸이며 `scoring.py` 98행 규모다
- 되돌릴 조건: 경쟁 제품이 DSR/시행횟수를 도입하면 1순위를 재검토
